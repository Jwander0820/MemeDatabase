# 個人迷因資料庫整體規格

- 版本：1.0
- 日期：2026-11-23
- 狀態：依本次討論整理的目標規格，功能尚待分階段實作。
- 文件關係：本文件定義產品與系統範圍；[DB 與搜尋規格](database-search-spec.md) 定義欄位、正規化、資料遷移及搜尋契約。既有 Agent 標籤作業依 [操作手冊](agent-image-tagging-guide.md) 執行，原階段設計保存於歷史區。

## 1. 目標與成功條件

建立本地優先、可自行架設的個人迷因資料庫。使用者可以用台詞、角色、作品、情境或替代說法找到圖片，並快速複製或下載使用；Agent 透過受控唯讀接口執行相同搜尋。

公開服務以不影響 VPS 既有服務為前提。若資源或維護成本不合適，保留私人使用與 Tunnel 加存取驗證的部署方式。公開程式碼供他人自建，與是否公開個人館藏分開決定。

核心驗收：以使用者提供的常用查詢及目標圖片建立 20–30 題搜尋案例，目標圖片應出現在前五筆；手機可完成搜尋、預覽與取圖；Agent 可取得有限筆結果與有效媒體網址。

## 2. 現況與限制

目前為 Python／Flask、原生 HTML/CSS/JavaScript、SQLite。本地已具備 Discord 匯入與增量同步、附件下載、縮圖、OCR、人工編輯、收藏、標籤候選與審核、JSON 查詢接口。

既有搜尋使用 LIKE 查作品、說話者、台詞及 OCR，尚未實作本規格的別名與相關度排序。R2 僅有預留欄位，未接入公開媒體流程；沒有完成公開管理權限或 MCP。

2026-11-23 盤點：1,076 筆、原始附件約 1.25 GB、縮圖約 12 MB、SQLite 約 1.58 MB。此為當時基線，不是容量上限；資料補齊由使用者後續處理，不要求本次完成全庫標記。

VPS 條件為 2 核 CPU、2 GB RAM、每月 0.5 TB 流量，另有其他服務。尚未量測剩餘資源與尖峰，不承諾現有主機一定能安全共機。

## 3. 使用角色與權限

| 角色 | 可執行操作 |
|---|---|
| 管理員（使用者本人） | 本機新增、匯入、編輯、刪除、OCR、標記、審核與發布 |
| 公開訪客 | 搜尋、篩選、瀏覽、預覽及取圖 |
| 授權 Agent | 透過唯讀 API／未來 MCP 搜尋及取得單筆資料 |
| 自建者 | 自行部署與管理自己的資料庫，不共用原作者憑證或館藏 |

公開服務不提供寫入路由；不能只在 UI 隱藏按鈕。公開訪客不得修改既有全域收藏。第一版不增加會員、多人協作、公開上傳或公開收藏系統。

## 4. 資料與搜尋需求

沿用圖片附件、圖片文字 quote_text、角色 speaker、作品 anime_title、正式標籤；新增 display_title 與單圖替代搜尋詞。作品欄位允許漫畫等來源，UI 統一稱為「作品」。非圖片 metadata 可逐步補齊。

分類標籤用於分類與篩選；替代詞用於「也可以這樣搜」，只對指定圖片有效，不建立全域同義詞。填過角色、作品、標籤不必重填；跨欄位重複不得造成重複結果或加分。

系統保存原文，另生成可重建的正規化搜尋資料。「復！活！」與「復活」的差異由系統處理；「我又回來了」等語意關聯由管理員補替代詞。搜尋涵蓋名稱、台詞、角色、作品、正式標籤、替代詞與既有 OCR；不搜尋內部 notes 或未接受候選。

支援多詞跨欄位命中、相關度排序、精確標籤篩選及穩定分頁。文字查詢與狀態等篩選取交集。公開版僅搜尋已發布 ready 資料，不能用參數繞過。

資料範例與必要驗收：

| 欄位 | 範例 |
|---|---|
| 名稱 | 烈海王復活 |
| 台詞 | 復！活！ |
| 角色 | 烈海王 |
| 作品 | 刃牙 |
| 標籤 | 復活 |
| 替代詞 | 我又回來了（驗收用示例，由管理員決定） |

「復活」「復！活！」「復 活」「烈海王」「刃牙」「烈海王 復活」均可找到該圖；新增替代詞後也可用該詞找到。測試採獨立資料，不自動將範例圖片加入正式館藏。

初期採 SQL 與可理解的欄位排序規則，不要求向量搜尋或線上模型推論。全文索引／語意搜尋依後續命中率和效能決定。具體 schema、匹配及排序優先序以 [DB 規格](database-search-spec.md) 為準。

## 5. UI 與取圖流程

### 公開搜尋介面

- 首頁以搜尋框、分類篩選及圖片結果為主，顯示有效的載入、錯誤、空結果狀態。
- 圖片卡片提供名稱、必要的角色／作品、少量標籤及縮圖。
- 支援預覽原圖、下載、複製圖片與複製連結；不支援剪貼簿圖片的瀏覽器或格式須提供下載／連結替代方式並明確提示。
- 區分網站詳細頁連結與直接媒體網址；可分享的永久詳細頁 URL 留待路由實作時定義。
- 列表使用縮圖與懶載入，原圖按需載入；GIF 規劃靜態預覽，避免列表自動載入大量動態原檔。
- 手機可輕鬆搜尋、關閉預覽與取圖；分頁失敗可重試，舊搜尋回應不可覆蓋新查詢。

### 本機管理介面

新增、缺圖、待審核、編輯與永久刪除集中管理模式，狀態以易懂中文呈現。保留既有收藏與候選審核。新增「梗圖名稱」「也可以這樣搜」欄位，替代詞以獨立詞條編輯，不用空白拆開一句話。

## 6. Agent API 與 MCP

先提供穩定、版本化唯讀 HTTP API；MCP 是後續可選的薄包裝，共用搜尋邏輯，不另做排序或資料副本。

目標能力為 search_memes(query, limit) 與 get_meme(id)，此為邏輯名稱，不代表目前已有同名端點。結果包含穩定 ID、顯示名稱、角色、作品、標籤、預覽與原圖 URL，必要時提供命中原因；不用 base64 內嵌整批圖片。

搜尋先回少量結果，圖片由呼叫端按需下載。限制查詢長度、頁面大小、可翻頁範圍與請求頻率；確切數值待實作與測量設定。回傳一致的驗證錯誤、無結果、未授權、限流及服務失敗格式。公開欄位採白名單，不直接序列化資料表全部欄位。

Agent 使用可撤銷 token 與配額，不要求解人機驗證；token 不放在公開前端。模型運算在 Agent 端，VPS 不因 API 請求啟動模型。第一版可只發 token 給本人，無須建立公開申請平台。

## 7. 架構與發布

```text
本機管理：匯入／OCR／標記／審核／本地原圖
                         │ 發布一致快照與媒體
             ┌───────────┴───────────┐
             ▼                       ▼
VPS：唯讀 SQLite＋Web/API         R2：縮圖／原圖
             │ 回傳網址               ▲
             ▼                       │ 直接取圖
         瀏覽器／Agent ───────────────┘
```

SQLite 為第一版部署後端，VPS 不常駐 OCR／GPU／視覺模型依賴。Web 所需依賴需與本機批次處理依賴分離，不直接完整安裝現有含 GPU 的依賴集合。

本機為單一編輯來源。發布程序產生白名單資料快照，檢查媒體與資料一致後切換版本；先準備媒體再發布引用，保留上一版本供回復。不能直接覆蓋正在使用的 DB，或在公開服務啟動時進行管理端 migration／taxonomy 寫入。發布版本與還原程序需另行實作驗證。

圖片從 R2 直接供應，VPS 不代理原圖。正式媒體分發使用自訂網域與快取；私有模式另設媒體權限，網站登入不代表公開媒體 URL 自動受到保護。

本地版本須可獨立使用，使用本地媒體路徑；公開版使用 R2 URL，不將 Windows 絕對路徑發布給訪客。備份包含 DB、新欄位、替代詞、圖片及必要設定，敏感設定獨立保護。同步鏡像不取代版本備份，須驗證還原。

## 8. 公開存取與防濫用

- 網站先以限流、快取及回傳大小限制保護，可疑／超量流量再考慮 Turnstile；不要求每次正常搜尋都驗證。
- Turnstile 若採用必須後端驗證 token；不能只顯示前端元件。
- Agent API 採 token、速率與每日額度，與訪客網站的存取流程分開。
- 公開服務只使用唯讀資料與接口；本機管理入口不隨公開站暴露。
- 正式環境使用生產 WSGI 服務，不能直接使用 Flask 開發伺服器。
- 私人 Tunnel 需搭配存取驗證；Tunnel 不會自動免除主機傳輸流量。
- 公開圖片可被直接取得，是否額外限制媒體存取須依公開／私人模式決定。

## 9. 資源驗收與部署決策

部署前記錄 VPS 既有服務的 CPU、可用 RAM、swap、磁碟與流量基線；試跑後量測新增常駐用量、尖峰、搜尋延遲及錯誤率。不得用本機查詢耗時當作 VPS 負載測試結果。

圖片列表只讀縮圖，原圖按需讀取，API 只回 metadata 與 URL。限制 worker／連線數，避免小主機因無限制併發或批次工作影響其他服務。

具體 RAM 上限、同時使用人數、延遲目標與限流值須依主機基線另定；尚無量測前不宣稱可支援特定流量。R2 免費額度由帳號其他專案共用，流量免費不等於操作無限免費，部署時重查價格與帳號用量。

若試跑造成既有服務延遲、swap 或資源壓力明顯上升，先停止公開擴張、降低配額或維持私人模式；不以額外加模型或資料庫掩蓋問題。

## 10. SQL 學習與 PostgreSQL 後續方向

採同一應用與搜尋契約，後續提供 SQLite／PostgreSQL 可選後端。學習內容包含資料建模、關聯表、唯一限制、交易、索引、分頁、查詢計畫與效能測量。

用相同資料及查詢比較兩個後端的命中、排序、延遲、索引大小與記憶體。索引根據 WHERE／JOIN／ORDER BY 設計，不假定一般 B-tree 能加速前後萬用字元的 LIKE，也不假定 trigram 適合所有中文兩字詞。PostgreSQL 可先僅在本機練習，正式部署不必同時跑兩種 DB。

## 11. 實作階段與退出條件

| 階段 | 交付項目 | 完成條件 |
|---|---|---|
| 1. DB 與搜尋 | 新欄位、替代詞、正規化、排序、migration | DB 規格驗收通過；既有資料不被覆蓋；副本可還原 |
| 2. UI | 搜尋首頁、管理模式、手機取圖 | 桌面與手機完整搜尋／取圖流程驗證；正常錯誤回復 |
| 3. Agent | 穩定唯讀 API、token、配額 | 真實 Agent 搜尋及取圖成功；任何寫入被拒絕 |
| 4. 私人部署 | 快照發布、R2、生產服務、備份、監測 | 主機資源與還原測試合格，不影響既有服務 |
| 5. 公開唯讀 | 訪客限流、公開欄位、媒體權限檢查 | 公開範圍明確；不可越權；資源符合事先設定門檻 |
| 後續可選 | MCP、PostgreSQL、全文或語意搜尋 | 有實際使用／學習需求且通過共用驗收 |

階段安排不等於已授權部署、stage、commit、push、開 PR 或發 release；執行時依當次明確授權進行。

## 12. 開源與待定事項

開源交付需包含適當授權檔、最小依賴、設定範例、啟動／發布／備份說明與示例資料。不得提交個人館藏、token、.env、模型或實際資料庫。授權種類尚未決定。

待實作時確認：公開館藏範圍、正式網域、R2 帳號剩餘額度、VPS 資源基線、配額數值、公開詳細頁路由與發布版本保留政策。這些待定項目不阻止先完成本地搜尋與 DB 階段。
