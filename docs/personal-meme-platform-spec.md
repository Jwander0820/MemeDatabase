# 個人迷因資料庫整體規格

- 版本：1.3
- 日期：2026-11-24
- 狀態：依本次討論整理的目標規格，功能尚待分階段實作。
- 文件關係：本文件定義產品與系統範圍；[DB 與搜尋規格](database-search-spec.md) 定義欄位、正規化、資料遷移及搜尋契約。既有 Agent 標籤作業依 [操作手冊](agent-image-tagging-guide.md) 執行，原階段設計保存於歷史區。

## 1. 目標與成功條件

建立本地優先、可自行架設的個人迷因資料庫。使用者可以用台詞、角色、作品、情境或替代說法找到圖片，並快速複製或下載使用；私人 Agent 透過選用唯讀 MCP 執行相同搜尋；公開站不提供 Agent 專用接口或 MCP。

公開服務以不影響 VPS 既有服務為前提。若資源或維護成本不合適，保留私人使用與 Tunnel 加存取驗證的部署方式。公開程式碼供他人自建，與是否公開個人館藏分開決定。

核心驗收：以使用者提供的常用查詢及目標圖片建立 20–30 題搜尋案例，目標圖片應出現在前五筆；手機可完成搜尋、預覽與取圖；Agent 可取得有限筆結果與有效媒體網址。

## 2. 現況與限制

目前為 Python／Flask、原生 HTML/CSS/JavaScript、SQLite。本地已具備 Discord 匯入與增量同步、附件下載、縮圖、OCR、人工編輯、收藏、標籤候選與審核、JSON 查詢接口。

本地搜尋後端已支援名稱、替代詞、正規化及相關度，UI 尚未整合新欄位與相關度預設，詳見搜尋後端實作紀錄。R2 僅有預留欄位，未接入公開媒體流程；沒有完成公開管理權限或 MCP。

2026-11-23 盤點：1,076 筆、原始附件約 1.25 GB、縮圖約 12 MB、SQLite 約 1.58 MB。此為當時基線，不是容量上限；資料補齊由使用者後續處理，不要求本次完成全庫標記。

VPS 條件為 2 核 CPU、2 GB RAM、每月 0.5 TB 流量，另有其他服務。尚未量測剩餘資源與尖峰，不承諾現有主機一定能安全共機。

## 3. 使用角色與權限

| 角色 | 可執行操作 |
|---|---|
| 管理員（使用者本人） | 本機新增、匯入、編輯、刪除、OCR、標記、審核與發布 |
| 公開訪客 | 搜尋、篩選、瀏覽、預覽及取圖 |
| 私人 Agent | 透過私人唯讀 MCP 搜尋及取得單筆資料，公開站不提供 MCP |
| 自建者 | 自行部署與管理自己的資料庫，不共用原作者憑證或館藏 |

公開服務不提供寫入路由；不能只在 UI 隱藏按鈕。公開訪客不得修改既有全域收藏。第一版不增加會員、多人協作、公開上傳或公開收藏系統。

## 4. 資料與搜尋需求

沿用圖片附件、圖片文字 quote_text、角色 speaker、作品 anime_title、正式標籤；新增 display_title 與單圖替代搜尋詞。作品欄位允許漫畫等來源，UI 統一稱為「作品」。非圖片 metadata 可逐步補齊。

分類標籤用於分類與篩選；替代詞用於「也可以這樣搜」，只對指定圖片有效，不建立全域同義詞。填過角色、作品、標籤不必重填；跨欄位重複不得造成重複結果或加分。

系統保存原文，另生成可重建的正規化搜尋資料。「復！活！」與「復活」的差異由系統處理；「我又回來了」等語意關聯由管理員補替代詞。搜尋涵蓋名稱、台詞、角色、作品、正式標籤、替代詞與既有 OCR；不搜尋內部 notes 或未接受候選。

支援多詞跨欄位命中、相關度排序、精確標籤篩選及穩定分頁。文字查詢與狀態等篩選取交集。公開版僅搜尋已發布 ready 資料，不能用參數繞過。

資料範例與必要驗收：

| 欄位 | 範例 |
|---|---|
| 名稱 | 烈海王復活 |
| 台詞 | 復！活！ |
| 角色 | 烈海王 |
| 作品 | 刃牙 |
| 標籤 | 復活 |
| 替代詞 | 我又回來了（驗收用示例，由管理員決定） |

「復活」「復！活！」「復 活」「烈海王」「刃牙」「烈海王 復活」均可找到該圖；新增替代詞後也可用該詞找到。測試採獨立資料，不自動將範例圖片加入正式館藏。

初期採 SQL 與可理解的欄位排序規則，不要求向量搜尋或線上模型推論。全文索引／語意搜尋依後續命中率和效能決定。具體 schema、匹配及排序優先序以 [DB 規格](database-search-spec.md) 為準。

## 5. UI 與取圖流程

### 公開搜尋介面

- 首頁以搜尋框、分類篩選及圖片結果為主，顯示有效的載入、錯誤、空結果狀態。
- 圖片卡片提供名稱、必要的角色／作品、少量標籤及縮圖。
- 支援預覽原圖、下載、複製圖片與複製連結；不支援剪貼簿圖片的瀏覽器或格式須提供下載／連結替代方式並明確提示。
- 區分網站詳細頁連結與直接媒體網址；可分享的永久詳細頁 URL 留待路由實作時定義。
- 列表使用縮圖與懶載入，原圖按需載入；GIF 規劃靜態預覽，避免列表自動載入大量動態原檔。
- 手機可輕鬆搜尋、關閉預覽與取圖；分頁失敗可重試，舊搜尋回應不可覆蓋新查詢。

### 本機管理介面

新增、缺圖、待審核、編輯與永久刪除集中管理模式，狀態以易懂中文呈現。保留既有收藏與候選審核。新增「梗圖名稱」「也可以這樣搜」欄位，替代詞以獨立詞條編輯，不用空白拆開一句話。

## 6. 網站 API 與私人 MCP

公開站只提供前端需要的版本化唯讀 HTTP API，不提供 Agent 專用 API、token 申請平台或 MCP。匿名網站 API 仍可能被自動化使用，使用 Nginx 限流控制基本資源消耗。

私人本機／自建 Docker 可選擇啟用官方 SDK 的無狀態 Streamable HTTP MCP，預設關閉、loopback 綁定，要求 bearer token 及 Host／Origin 驗證。僅 search_memes(query, limit) 與 get_meme(id)，查 ready 資料並回有限 metadata 與私人媒體網址，不提供寫入、任意 SQL 或檔案操作。

兩種查詢共用搜尋契約，模型運算在呼叫端。詳細接口、依賴與驗證見 [後端操作文件](backend-refactor.md)。

## 7. 架構與發布

```text
本機管理：匯入／OCR／標記／審核／本地原圖
                         │ 發布一致快照與媒體
             ┌───────────┴───────────┐
             ▼                       ▼
VPS：唯讀 SQLite＋Web/API         R2：縮圖／原圖
             │ 回傳網址               ▲
             ▼                       │ 直接取圖
         瀏覽器／Agent ───────────────┘
```

SQLite 為第一版部署後端，VPS 不常駐 OCR／GPU／視覺模型依賴。Web 所需依賴需與本機批次處理依賴分離，不直接完整安裝現有含 GPU 的依賴集合。

本機為單一編輯來源。發布程序產生白名單資料快照，檢查媒體與資料一致後切換版本；先準備媒體再發布引用，保留上一版本供回復。不能直接覆蓋正在使用的 DB，或在公開服務啟動時進行管理端 migration／taxonomy 寫入。發布版本與還原程序需另行實作驗證。

圖片從 R2 直接供應，VPS 不代理原圖。正式媒體分發使用自訂網域與快取；私有模式另設媒體權限，網站登入不代表公開媒體 URL 自動受到保護。

本地版本須可獨立使用，使用本地媒體路徑；公開版使用 R2 URL，不將 Windows 絕對路徑發布給訪客。備份包含 DB、新欄位、替代詞、圖片及必要設定，敏感設定獨立保護。同步鏡像不取代版本備份，須驗證還原。

## 8. 公開存取與防濫用

- 網站先以限流、快取及回傳大小限制保護，可疑／超量流量再考慮 Turnstile；不要求每次正常搜尋都驗證。
- Turnstile 若採用必須後端驗證 token；不能只顯示前端元件。
- 公開站不提供 Agent 專用 API 或 MCP；私人 MCP 採 token 與回傳上限，預設僅 localhost。
- 公開服務只使用唯讀資料與接口；本機管理入口不隨公開站暴露。
- 正式環境使用生產 WSGI 服務，不能直接使用 Flask 開發伺服器。
- 私人 Tunnel 需搭配存取驗證；Tunnel 不會自動免除主機傳輸流量。
- 公開圖片可被直接取得，是否額外限制媒體存取須依公開／私人模式決定。

## 9. 資源驗收與部署決策

部署前記錄 VPS 既有服務的 CPU、可用 RAM、swap、磁碟與流量基線；試跑後量測新增常駐用量、尖峰、搜尋延遲及錯誤率。不得用本機查詢耗時當作 VPS 負載測試結果。

圖片列表只讀縮圖，原圖按需讀取，API 只回 metadata 與 URL。限制 worker／連線數，避免小主機因無限制併發或批次工作影響其他服務。

具體 RAM 上限、同時使用人數、延遲目標與限流值須依主機基線另定；尚無量測前不宣稱可支援特定流量。R2 免費額度由帳號其他專案共用，流量免費不等於操作無限免費，部署時重查價格與帳號用量。

若試跑造成既有服務延遲、swap 或資源壓力明顯上升，先停止公開擴張、降低配額或維持私人模式；不以額外加模型或資料庫掩蓋問題。

## 10. SQL 學習與 PostgreSQL 後續方向

採同一應用與搜尋契約，後續提供 SQLite／PostgreSQL 可選後端。學習內容包含資料建模、關聯表、唯一限制、交易、索引、分頁、查詢計畫與效能測量。

用相同資料及查詢比較兩個後端的命中、排序、延遲、索引大小與記憶體。索引根據 WHERE／JOIN／ORDER BY 設計，不假定一般 B-tree 能加速前後萬用字元的 LIKE，也不假定 trigram 適合所有中文兩字詞。PostgreSQL 可先僅在本機練習，正式部署不必同時跑兩種 DB。

## 13. 已確認的架構決策（2026-11-24，實作狀態見第 15 節）

- 前後端分離：前端為可獨立建置／供應的靜態 UI，透過 JSON API 存取資料；後端不靠模板注入業務資料。可由同一網域反向代理，不要求額外多開容器。管理 UI 與公開 UI 共用搜尋元件，公開產物不包含管理入口，公開後端不註冊管理路由。
- 圖片來源使用通用原圖／縮圖網址，不綁定 R2。本機檔案、發布包靜態縮圖、R2 及允許直接使用的外部 HTTPS 來源各有適用模式。
- 本機新增發布管理流程：預覽待公開項目與欄位、逐項警示／排除、驗證後產生公開快照與發布報告。預設不公開新項目，需有明確的發布選擇；ready 僅表示資料可用，不等於同意公開。
- 公開匯出採欄位白名單並禁止本地路徑、內部備註與原始來源紀錄外洩。缺少可用媒體、非法網址／協定、缺失必要欄位等阻擋發布；報告包含原因與數量，不能默默略過錯誤並宣稱全數成功。
- 機器檢查只能發現可定義的問題，無法保證圖中文字、肖像或敏感資訊合規，仍需人工預覽。從發布清單排除不刪除本機原圖；永久刪除是獨立、明確確認的管理操作。
- 第一版直接使用 SQLite 搜尋，不增加全庫 dict 快取。先優化查詢並測量延遲與 RSS，確認瓶頸後才考慮記憶體索引；dict 的 ID 查找快不代表任意文字搜尋自動有索引。
- 熱更新採版本化不可變 SQLite 快照：上傳暫存、驗證、完成發布後原子切換版本指標；失敗保留舊版與錯誤紀錄。每次請求解析一次版本，以唯讀連線完成該次查詢後關閉；新請求開啟新版本，舊請求繼續使用舊版本。掛載整個發布目錄，不單獨綁定被替換的 DB 檔。保留舊檔至舊請求結束，不能讀取上傳中的 DB。
- 每次請求讀取版本指標即可看到已發布版本，不需等待午夜。定時發布是未來可選項，現在不建立排程。多 worker 使用同一版本指標；單一請求內計數、分頁與內容必須固定同版，不能沿用長期連線而忽略版本切換。
- 第一版列表使用現有最長邊 420 px 縮圖，驗收手機文字可讀性；允許下載縮圖與選擇原圖，細字圖片保留較大版本。全部圖片衍生版本在本機生成，發布服務不處理壓縮。尺寸保持比例、不放大；360／480 為後續可選評估。
- 2026-11-24 實測：1,070 張現有 WebP 縮圖最長邊至多 420 px、quality=78，合計約 12 MB。原附件未經本專案統一壓成 720p：可解碼圖片最長邊中位數 1,920 px、最大 4,080 px。360／480 成品大小與文字可讀性尚未測量。
- 小型縮圖可隨發布包存 VPS 掛載目錄，由靜態服務供應，不寫進 Docker 映像；原圖仍可外部直連。此方式減少外部物件讀取但增加 VPS 出站流量，是否採用須連同 CDN 快取與流量額度評估。舊媒體版本須保留到舊請求不再使用後才清理。

## 14. Nginx 與容器部署設計（已選定，待實作）

採 Nginx 供應前端靜態檔與 VPS 縮圖，將 /api/ 轉送到獨立 Python 搜尋服務。使用 Compose 管理 Nginx 與搜尋後端兩個服務；若 VPS 已有入口代理，部署時先確認 port 與轉送安排。前後端共用外部網域但獨立建置與 API 契約，不要求另建跨網域流程。

```text
本機完整版：管理前端 → 管理 API → 完整 SQLite／本地圖片
                                  ↓ 人工選擇、檢查、匯出
                         公開 SQLite＋縮圖發布包
                                  ↓ 同步至 VPS 持久化目錄
瀏覽器 → HTTPS／可選 Tunnel → Nginx
                              ├─ /       前端靜態檔
                              ├─ /media/ 縮圖（唯讀掛載）
                              └─ /api/   Python 搜尋 API
                                              ↓
                                      公開 SQLite（唯讀掛載）
瀏覽器 ─────────────────────────→ R2／其他外部原圖網址
```

### 持久化與隔離

- 公開 DB 的版本目錄與縮圖目錄保存在 VPS，掛載整個目錄，資料不寫入映像或容器可丟棄層。容器重建不刪除發布資料，但仍需備份。
- 搜尋服務僅讀取公開 DB；Nginx 僅掛載公開媒體與靜態前端，不掛載 DB，也不將資料庫目錄設定為公開路徑。停用目錄列表。
- 原圖可在 R2 或其他合法可用的外部網址，不要求複製到 VPS。本機完整版可完全離線使用本地圖片，無須 R2。
- 新媒體先就緒再發布引用它的 DB。資料更新只切換已驗證的快照，不需重建映像；程式、依賴或不相容 schema 改變才需配套更新服務。
- 公開後端不包含 OCR／批次壓縮／管理路由，不在啟動時 migration。requirements.txt 為無 Pillow 的公開基礎，requirements-admin.txt 加入圖片管理依賴；正式 WSGI 已選用 Waitress。

### 靜態快取

- 縮圖使用內容雜湊檔名，內容更新即產生新 URL；不可對同 URL 換內容卻設定永久快取。
- Nginx 設定圖片及帶版本的前端資源 Cache-Control。HTML 採短快取或重新驗證，避免新版前端入口長期停留舊版。
- 瀏覽器快取減少同一訪客的重複下載；CDN 為可選，命中才能減少 VPS 出站流量。本機磁碟／OS 快取只減少磁碟讀取，不能免除網路傳輸。
- 第一版不啟用搜尋 API 長時間回應快取，不建立額外大型記憶體快取服務，避免發布後仍提供舊結果。

### 維護與驗收

Nginx 配置維持靜態供應與 API 代理用途，不增加管理面板。初期評估 1 個 worker，實際用量以 VPS 測量為準，不把「數十 MB」規劃估算當成保證。部署時設定日誌輪替／容量、健康檢查及重啟策略，關注映像安全更新。直接對外需憑證續期流程；Tunnel 模式另行配置入口與權限。定期資料發布無須修改 Nginx 設定。

驗收包含：外部無法下載 DB／內部檔案；無管理路由；更新縮圖可見；舊版本查詢不中斷，新請求看到已發布新版；失敗發布保留舊版；容器重建資料仍在；快取標頭正確；日誌不無限制成長。未確認 VPS 既有服務與資源基線前不直接部署。

參考：[Nginx 入門](https://nginx.org/en/docs/beginners_guide.html)、[快取標頭](https://nginx.org/en/docs/http/ngx_http_headers_module.html)、[設定重載與日誌](https://nginx.org/en/docs/control.html)、[Docker bind mounts](https://docs.docker.com/engine/storage/bind-mounts/)。
