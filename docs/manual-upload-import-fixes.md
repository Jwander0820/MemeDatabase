# 手動新增與本機匯入修正規格

狀態為已完成（2026-11-26），四項皆有自動測試涵蓋。本文件補充[本機圖片匯入與管理頁編輯規格](local-import-editor-spec.md)，涵蓋私人管理頁的手動新增，以及 `import-web-memes` 對舊附件的去重檢查。驗收使用暫存館藏。

## 1. 純中文檔名可以上傳

修正前，同一張有效 PNG 以 `烈海王復活.png` 上傳會得到 HTTP 400，改名為 `meme.png` 則得到 201。原因是清理檔名後才取副檔名，純中文主檔名可能被整段移除。以下列出已實作的行為與回歸驗收。

**預期行為**：從原始檔名取得副檔名並統一大小寫，再沿用既有格式白名單與圖片解碼檢查。實際附件路徑繼續由系統產生。點選與拖入檔案共用相同規則。

**驗收**：分別以 `烈海王復活.png`、`復活.PNG`、`meme.png` 上傳有效 PNG，均應成功新增，重新開啟可查看圖片。將純文字檔改名為 `復活.png` 上傳，應回傳 400，館藏與附件目錄均無新增資料。

## 2. 上一筆上傳回應不能清空下一筆草稿

修正前，送出 A 後，如果使用者關閉視窗、重新開啟並開始編輯 B，A 的成功回應仍會關閉當前視窗，觸發表單重設。

**預期行為**：送出時記錄本次開啟的表單識別值。成功、失敗與請求結束時，都先確認目前視窗是否仍屬於該次操作，再決定能否關閉、清空、顯示欄位錯誤、開啟詳情或解除送出鎖定。舊請求的結果可用全頁提示回報。關閉視窗不代表已取消伺服器端建檔。

**驗收**：延遲 A 的回應，關閉後重開視窗，替 B 選圖、輸入台詞，再分別讓 A 成功與失敗。B 的視窗、預覽、台詞都要保留，焦點不跳到 A。若 B 也正在送出，A 的回應不得提前解鎖 B 的送出按鈕。

## 3. 分開回報建檔結果與清單更新結果

修正前，收到建檔成功回應後，前端會關閉表單，等統計、清單與詳情更新後才提示成功。若中途失敗，使用者可能誤以為要重新上傳。

**預期行為**：收到 HTTP 201 與新條目的識別值時，即在視窗外顯示「已新增」。若後續讀取失敗，提示「已新增，畫面更新失敗」，並提供重試讀取的入口。重試只讀取統計、清單或已建立的條目。同一次操作只送出一次建檔 POST。若建檔結果尚未確認，例如送出後連線中斷，應提示使用者先核對館藏。

**驗收**：讓 POST 成功，再分別模擬統計、清單、詳情讀取失敗。三種情況都應看得到已建檔的結果；恢復連線並重試後可找到該筆，資料庫仍只有一筆。另測 POST 回傳驗證錯誤時，原視窗應保留草稿並顯示原因。

## 4. 舊附件讀取失敗只回報一次

舊版匯入的附件可能尚無內容指紋。修正前，匯入器掃描時若遇到權限或檔案鎖定錯誤，會在處理下一張新圖時再次掃描，讓多筆有效資料都被標成錯誤。

**已實作決策**：為維持跨批去重保證，每批在寫入第一張本機圖前完成一次舊附件核對。若存在但無法讀取的舊附件使核對無法完成，暫停該批本機圖寫入，於批次摘要列出受影響的舊附件識別值及原因，各回報一次。本機新圖標記為「未處理」，網址列仍沿用網址去重。原本就缺少原檔的舊紀錄沿用既有規格。預檢採相同判定並維持唯讀。

**驗收**：準備一張讀取時會發生權限錯誤的舊附件、兩張有效本機新圖與一筆有效網址。確認舊附件只掃描並回報一次，兩張本機圖均未寫入，網址列可正常處理。恢復舊附件讀取權限後重跑，本機新圖依內容判為新增或重複，先前成功的網址列回報重複。
