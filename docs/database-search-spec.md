# 個人迷因資料庫與搜尋規格

- 版本：1.0
- 更新日期：2026-11-23
- 狀態：本地 schema、管理 API 與搜尋核心已實作；UI、發布與索引優化待完成。詳見 [實作紀錄](backend-search-implementation.md)。
- 範圍：沿用 SQLite，補充梗圖名稱、單圖替代搜尋詞與共用搜尋契約。主庫已完成備份與加法式遷移，詳細證據見實作紀錄。

## 1. 設計邊界

本機負責匯入、OCR、縮圖、人工編輯、標籤審核與資料發布。公開站僅提供搜尋、瀏覽、取圖及唯讀 Agent API，不安裝或執行 OCR／視覺模型，也不提供新增、修改、刪除接口。

第一版以 SQLite 為正式後端。未來可為 SQL 學習加入 PostgreSQL 實作，共用 UI、API、資料意義與驗收案例；不要求兩個資料庫同時部署，也不建立雙向同步。PostgreSQL 遷移及 R2 部署不屬於本次 schema 更新。

## 2. 使用者提供的資料

| UI 欄位 | 儲存位置 | 規則 |
|---|---|---|
| 圖片 | 既有 attachments | 沿用附件識別與媒體流程 |
| 梗圖名稱 | 新增 meme_entries.display_title | 選填；如「烈海王復活」 |
| 圖片文字 | 既有 meme_entries.quote_text | 保留「復！活！」等原文；無文字時可為空字串 |
| 角色／說話者 | 既有 meme_entries.speaker | 選填，不知道時留空，不要求推測 |
| 作品 | 既有 meme_entries.anime_title | 選填；UI 稱「作品」，允許漫畫等來源，不更名既有 DB 欄位 |
| 分類標籤 | 既有 tags、entry_tags | 可點選篩選的分類／情境，例如「復活」 |
| 也可以這樣搜 | 新增 entry_search_aliases | 選填，每個替代搜尋詞獨立一筆 |

未提供名稱時，顯示端依序使用「角色＋圖片文字」、圖片文字、作品、固定提示「未命名梗圖」作為後備名稱；空白內容跳過。後備名稱不寫回 display_title，搜尋以實際來源欄位為準。

metadata 允許逐步補齊，不強制每張圖填完整。notes 仍為內部備註，不默認作為公開搜尋資料；ocr_text 沿用原有輔助文字，不覆蓋人工台詞。

## 3. 標籤與替代搜尋詞

- 標籤表示分類，例如「復活」，供列表瀏覽與精確篩選。
- 替代搜尋詞表示使用者可能的說法，例如「我又回來了」；僅對指定梗圖有效，不建立全域同義詞關係。
- 一般搜尋同時查標籤與替代詞；點選標籤只查正式 entry_tags，不查替代詞。
- 已填的角色、作品、標籤不必重填為替代詞。
- 跨欄位重複不造成重複結果或重複加分，也不自動刪掉使用者在另一欄保存的內容。
- Agent 候選標籤未接受前不納入搜尋。替代詞第一版由管理員維護；不擴充既有 Agent JSONL 格式，不將模型結果自動轉成正式替代詞。

## 4. Schema 變更

採加法式 migration，保留既有欄位、鍵值、標籤來源、審核資料及附件關聯。

### 4.1 梗圖名稱

新增 nullable TEXT 欄位 meme_entries.display_title。輸入去除首尾空白；空內容存 NULL。既有資料預設 NULL，不由 migration 猜測名稱。

### 4.2 替代搜尋詞

SQLite 結構如下，已實作：

```sql
CREATE TABLE entry_search_aliases (
    entry_key TEXT NOT NULL,
    alias_text TEXT NOT NULL,
    alias_normalized TEXT NOT NULL,
    normalization_version INTEGER NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (entry_key, alias_normalized),
    FOREIGN KEY (entry_key) REFERENCES meme_entries(key) ON DELETE CASCADE,
    CHECK (length(trim(alias_text)) > 0),
    CHECK (length(alias_normalized) > 0)
);
```

alias_text 保存使用者文字，alias_normalized 由程式產生，不接受外部直接指定。同一梗圖正規化後相同的替代詞只保留一筆；不同梗圖可使用相同詞。新增或編輯空白／正規化後為空的詞時，明確回報無效輸入。

編輯替代詞集合以交易處理，與該 entry 的 updated_at 一起更新；替代詞刪除不影響標籤。永久刪除 entry 時一併移除替代詞及衍生搜尋資料。

### 4.3 衍生搜尋資料

搜尋用正規化內容與索引為可重建資料，原始欄位才是主資料。第一版可採保留欄位來源的搜尋投影；不把所有欄位無分隔串成單一字串，以免跨欄位產生虛假片語命中。

實體搜尋投影表／FTS 結構在實作時依測量決定，不在本版強制選擇。名稱、台詞、角色、作品、正式標籤、替代詞或 OCR 更新後，必須在同次更新流程完成搜尋資料更新；全量重建結果須一致。保存 normalization_version，規則更新時重建並處理替代詞唯一鍵碰撞，不可直接改版本號而留下舊索引。

## 5. 搜尋契約

### 5.1 正規化

原始資料不變；查詢和搜尋欄位使用相同版本的規則：Unicode NFKC、拉丁文字 casefold、使用專案既有 OpenCC 轉換設定統一繁簡、整理空白。另產生移除空白與 Unicode 標點的緊縮比較形式，使「復！活！」「復活」「復 活」可匹配。不可任意刪除其他符號，例如加號、表情符號。

先保存原查詢的空白分詞邊界，再對各詞正規化；同時保留整句緊縮形式。全為空白／標點的非空查詢回傳可理解的驗證錯誤，不轉成無條件全庫搜尋。真正空查詢則維持瀏覽模式。

### 5.2 命中與篩選

搜尋欄位為 display_title、quote_text、speaker、anime_title、正式標籤、替代詞、ocr_text；不搜尋 notes、pending／rejected 候選或來源訊息內容。

多詞查詢預設 AND，各詞可跨欄位命中。例如「烈海王 復活」可分別命中角色與台詞。同時允許整句緊縮形式在單一欄位命中，以支援「復 活」對「復！活！」的匹配。這不等於中文自動斷詞，也不自動推論未設定的同義詞。

狀態、標籤等篩選與文字搜尋取交集。公開站僅能查已發布的 ready 資料，不接受透過 status=all 讀取內部資料。SQL 必須使用參數化查詢；LIKE 中使用者輸入的 %、_ 等符號按字面處理，不允許意外擴大搜尋。

### 5.3 排序

有搜尋詞時預設相關度排序；無搜尋詞時沿用瀏覽排序。相關度依下列層級優先：名稱完全符合、正式標籤／替代詞完全符合、角色／作品完全符合、人工名稱／台詞等部分符合、OCR 符合。整句完全符合優先於僅部分命中。

同一查詢詞於同張圖多處命中，取最佳層級而非重複累加；不同標籤來源的同名標籤也不加倍計分。不同查詢詞先去重，再計算命中品質。最後以 updated_at DESC、key ASC 打破同分，確保分頁順序穩定。具體分數可在實作時決定，但需符合此相對順序與驗收案例；顯式選擇其他排序時尊重選擇。

## 6. 索引與雙後端原則

- 替代詞的複合主鍵處理單圖唯一性及關聯查詢；全庫精確詞查詢可評估 (alias_normalized, entry_key) 索引。
- 依實際 WHERE、JOIN、ORDER BY 評估標籤關聯、狀態與時間的索引；不無條件為所有欄位建索引。
- 一般 B-tree 不視為任意位置 LIKE 的加速保證；「復活」兩字查詢必須獨立驗收，不假設 trigram 可以解決。
- SQLite 與未來 PostgreSQL 可使用不同 SQL／索引，但對同一資料集須符合相同命中及排序契約。
- 用具代表性的資料量與查詢測量計畫、延遲、索引容量及記憶體；不得單憑索引存在宣稱加速。

## 7. 本機 UI、API 與公開發布

本機表單新增「梗圖名稱」「也可以這樣搜」；標籤欄保留「分類標籤」。替代詞以獨立詞條編輯，勿用空白切分一句替代說法。查詢、編輯與匯出以陣列交換替代詞，不使用逗號拼接作為正式資料格式。

UI 與 Agent 共用搜尋服務，不各自維護另一套排序。公開回應使用明確欄位白名單；不輸出本地路徑、私密來源紀錄、notes 或候選審核資料。正式公開前仍需獨立完成唯讀權限、限流、Agent token、媒體分發與部署驗證。

本機為單一編輯來源，發布一致的公開資料快照與媒體。搜尋衍生內容由本機準備，公開站不因搜尋觸發 OCR 或 AI。未來公開程式啟動不得沿用會修改 schema／同步 taxonomy 的管理初始化流程；採已完成 migration 的快照與唯讀連線。

## 8. Migration 與相容性

1. 使用 SQLite backup API 備份，先在副本驗證；不可直接複製正在寫入的 DB 當作一致性保證。
2. 冪等新增 display_title 與替代詞表；既有名稱為 NULL，替代詞集合為空。
3. 不從 notes、OCR 或候選標籤自動推測別名；不修改既有人工修正。
4. 在副本驗證重建搜尋資料、外鍵、筆數及原始欄位一致性，再安排正式 migration。
5. 備份／發布格式須保留名稱與替代詞；既有 CSV 欄位不可被挪用。需要可回匯的新格式時另訂版本；舊格式缺少新欄位表示不修改，不是清空。
6. Discord 重匯、OCR 重跑、候選審核不得覆蓋人工梗圖名稱 display_title 或替代詞；既有 anime_title 維持既有保護行為。
7. 回復以 migration 前備份為基準；新版本產生的修改需另保存，不能假設還原舊備份會保留它們。

## 9. 驗收案例

使用獨立測試資料，勿把使用者範例自動寫入館藏：名稱「烈海王復活」、台詞「復！活！」、角色「烈海王」、作品「刃牙」、標籤「復活」、替代詞「我又回來了」。

- 「復活」「復！活！」「復 活」「烈海王」「刃牙」「我又回來了」「烈海王 復活」均可找到該圖。
- 「烈海王 不存在詞」不應命中；別名不向其他復活梗圖全域擴散。
- 點「復活」標籤可找到該圖；僅有「復活」別名、沒有該標籤的另一張圖不被標籤篩選選中。
- 相同詞重複出現在標籤、別名或多個標籤來源時，只回傳一筆且不重複加分。
- 只有 OCR 命中的其他圖排序低於人工正式資料的完全命中；排序同分時分頁穩定。
- 原始台詞保持「復！活！」；正規化不改寫使用者資料。
- 替代詞更新／刪除後搜尋立即一致；刪除 entry 無殘留別名或搜尋資料。
- migration 可重跑，備份可還原，舊資料與附件不受覆蓋。
- 公開服務無寫入／OCR 接口，無法讀取未發布資料或內部欄位。
